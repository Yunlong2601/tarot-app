# Backend (Cloudflare Worker)

TypeScript + Hono. Proxies AI readings so the app never holds an LLM key.

## Endpoints
- `POST /v1/install` `{installId}` -> `{token}`. Anonymous 12 h token (HS256 JWT). **Returns 501 until device attestation (App Attest / Play Integrity) is implemented**, unless `ALLOW_UNATTESTED_INSTALLS=true` (local testing only, never in production).
- `POST /v1/reading` (Bearer token) `{spread: single|three|celtic, cards: [{id, reversed}], question?}` -> `{reading, disclaimer}`.
- Reading replies now carry `reading` (plain text), `structured` (cards, overview, reflection question, small step; null on fallback), `fallback` (true when a stored-text reading replaced an unsafe or malformed model reply) and the disclaimer. A crisis wording in the question returns `{crisis: true, message}` with no model call and nothing logged (fixed care message in `src/knowledge.ts`; check the numbers and sites before launch). `READING_PROMPT_VERSION` in `src/reading.ts` identifies the prompt.
- `POST /v1/followup` (Bearer token, **Premium only**) `{spread, cards, question?, reading, followup}` -> `{answer, disclaimer}`. The server stores no readings, so the app sends the earlier reading text back as context; it is treated as untrusted (inside `<reading>` tags, length-capped). Limit 30 a day per install, counted separately from readings.
- `GET /health`.

## Rules enforced server-side
- Spreads: 14, defined in `src/spreads.ts` (id, name, purpose, position labels). `single` and `three` are free; every other spread needs Premium, except one free trial reading per install (`countTrial` in D1; a reinstall resets it, like the daily limit).
- Input validation: spread/card count match, known unique card ids, question <= 300 chars, control characters and `<>` stripped, body <= 4 KB.
- Card names come from the server (`src/cards.ts`, generated by `scripts/gen-cards.mjs`); the client cannot inject card text.
- Prompt-injection defence: question only in the user turn inside `<question>` tags, system prompt says to treat it as untrusted; output is checked (`checkOutput`).
- Multi-card spreads need premium, checked via the Qonversion REST API (fails closed; needs `QONVERSION_SECRET_KEY`, Phase E).
- Limits: free 2 readings/day (owner decision 2026-10-17), premium 50/day (D1 count), 10 requests/minute per install and 30/minute per IP (KV), global daily token cap (`GLOBAL_DAILY_TOKEN_CAP`, default 2,000,000) as a kill switch.
- Token usage is logged per request in D1 (`usage` table). Questions and readings are never stored.
- Model: `LLM_MODEL` (default `claude-haiku-5-5`), effort `low`, no sampling parameters.

## Local run (verified on 2026-10-16)
```bash
cd backend
npm install
cp .dev.vars.example .dev.vars        # use made-up local values; never commit
npx wrangler d1 migrations apply shentarot --local
npm run dev                            # http://localhost:8787
scripts/smoke.sh http://localhost:8787
```
Local mode uses a real (local) D1 and KV, so the SQL and routing are exercised. Without an `ANTHROPIC_API_KEY` the last step returns 502 (expected); everything before it should print `ok`.

## Deploy runbook (needs your accounts; nothing here has been done yet)
1. **Cloudflare account** (free plan is enough to start). `npx wrangler login` opens a browser to approve.
2. **Create resources:** `npx wrangler d1 create shentarot` and `npx wrangler kv namespace create KV`. Paste the two ids into `wrangler.toml` (replace the `REPLACE_...` values) and commit that change.
3. **Migrate:** `npx wrangler d1 migrations apply shentarot --remote`.
4. **Anthropic:** create an account, add billing, set a **monthly spend limit** (for example US$10), create an API key.
5. **Secrets** (each prompts for the value; never put them in files or chat):
   ```bash
   npx wrangler secret put JWT_SECRET            # long random string
   npx wrangler secret put HASH_SALT             # another long random string
   npx wrangler secret put ANTHROPIC_API_KEY
   npx wrangler secret put QONVERSION_SECRET_KEY # after Qonversion setup (Phase E doc)
   npx wrangler secret put OPENAI_API_KEY        # optional: GPT-6 Luna fallback (see docs/own-key-and-providers.md)
   ```
   Generate random strings with `openssl rand -base64 48`.
6. **Deploy:** testing phase (before App Attest / Play Integrity): `npm run deploy:beta` (allows installs without attestation, cap 500,000 tokens a day). Public launch: `npm run deploy` (attestation required). Note the URL (`https://shentarot-api.<your-subdomain>.workers.dev`).
7. **Limits:** keep `GLOBAL_DAILY_TOKEN_CAP` low at first (default 2,000,000 tokens a day is about US$1 of Haiku output at the plan's prices; verify current prices).
8. **Build the app against it:** the live URL is in `app/config/live.json` (not a secret): `cd app && flutter run --dart-define-from-file=config/live.json`.

### Device attestation (decision needed before a public launch)
`POST /v1/install` returns 501 in production until App Attest (iOS) / Play Integrity (Android) is implemented, because without it anyone can mint install IDs. Options:
- **Recommended:** implement App Attest and Play Integrity before the public launch. Needs your Apple Team ID, final bundle ID and a Google Cloud project for Play Integrity.
- **TestFlight beta only:** set `ALLOW_UNATTESTED_INSTALLS=true` as a Worker variable with a low Anthropic spend limit and low `GLOBAL_DAILY_TOKEN_CAP`. Worst case, someone burns the daily cap (service stops for the day) or your spend limit. **Remove it before the public release.**
