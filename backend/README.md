# Backend (Cloudflare Worker)

TypeScript + Hono. Proxies AI readings so the app never holds an LLM key.

## Endpoints
- `POST /v1/install` `{installId}` -> `{token}`. Anonymous 12 h token (HS256 JWT). **Returns 501 until device attestation (App Attest / Play Integrity) is implemented**, unless `ALLOW_UNATTESTED_INSTALLS=true` (local testing only, never in production).
- `POST /v1/reading` (Bearer token) `{spread: single|three|celtic, cards: [{id, reversed}], question?}` -> `{reading, disclaimer}`.
- `GET /health`.

## Rules enforced server-side
- Input validation: spread/card count match, known unique card ids, question <= 300 chars, control characters and `<>` stripped, body <= 4 KB.
- Card names come from the server (`src/cards.ts`, generated by `scripts/gen-cards.mjs`); the client cannot inject card text.
- Prompt-injection defence: question only in the user turn inside `<question>` tags, system prompt says to treat it as untrusted; output is checked (`checkOutput`).
- Multi-card spreads need premium, checked via the RevenueCat REST API (fails closed; needs `REVENUECAT_SECRET_KEY`, Phase E).
- Limits: free 1 reading/day, premium 20/day (D1 count), 10 requests/minute per install and 30/minute per IP (KV), global daily token cap (`GLOBAL_DAILY_TOKEN_CAP`, default 2,000,000) as a kill switch.
- Token usage is logged per request in D1 (`usage` table). Questions and readings are never stored.
- Model: `LLM_MODEL` (default `claude-haiku-5-5`), effort `low`, no sampling parameters.

## Setup from zero
```bash
cd backend
npm install
cp .dev.vars.example .dev.vars        # fill in values; never commit
npx wrangler d1 create veilscan       # paste database_id into wrangler.toml
npx wrangler kv namespace create KV   # paste id into wrangler.toml
npx wrangler d1 migrations apply veilscan --local
npm run dev
```
Deploy: `npx wrangler login`, apply migrations without `--local` (`--remote`), set secrets with `npx wrangler secret put JWT_SECRET` (also `HASH_SALT`, `ANTHROPIC_API_KEY`, `REVENUECAT_SECRET_KEY`), then `npm run deploy`.

## Test
```bash
npm run typecheck && npm test
```
Tests use in-memory fakes and never call Anthropic or RevenueCat.

## Dependency audit (run before every release)
```bash
npm audit --omit=dev
```
Dependencies are pinned to exact versions in `package.json`.

## Not yet verified
- Nothing here has been deployed or run against the real Anthropic API, D1 or KV. The Anthropic request shape (`output_config: {effort: "low"}`) type-checks against the SDK but has not been called live.
- KV burst counters are not atomic; they are a brake, not a hard guarantee. The daily caps use D1.
- Measure `usage.cache_read_input_tokens` before relying on prompt caching (the system prompt may be below the minimum cacheable size).
